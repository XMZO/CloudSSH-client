## 外部 AI 读取已打开标签的终端内容

> 状态：待定（2026-10-21 记下）

**现状**

- **终端里的 AI 助手**（网页版 Agent，Worker 里跑）已经能看到这个会话的终端输出：Worker 为每个会话留着最近约 5 万字符的原始输出，每一步自动带上最后 200 行（最多 4000 字），模型还能用 `read_terminal_context` 工具多读一些（最多 1.6 万字）。只限这条连接；带颜色控制码；完整重连后清空。
- **通过命令行 / MCP 接入的外部 AI**（Claude Code、Codex、Cursor、远程 MCP……）看不到你开着的标签：它们的工具（`exec`、`read_file`、`start_job` 等）都在单独的通道上执行，只能自己再跑一遍命令了解状态，不知道你刚才在终端里输入了什么、看到了什么。

**打算**

- 命令行与 MCP 增加两个只读工具：列出桌面客户端里开着的会话（标签名、主机 ID、连接状态），以及读取某个会话终端最近若干行（去掉颜色控制码，按 xterm 屏幕与回滚内容取，不是原始字节流）
- 经桌面客户端读取（客户端开着才有，与 AI 跨服务器操作同一条本机通道），不经 Worker
- **默认关**；打开后每次读取在客户端弹出允许（可选“这个会话本次都允许”），设置里能看到最近被读过的记录
- 结果有界（行数与字数上限），并照命令行现有规则对疑似密钥、令牌做遮盖；终端内容在给模型时标成不可信数据，不构成操作授权
- 远程 MCP 不提供（读的是本机客户端，云端碰不到）

**要注意**

- 终端里可能有密码提示后的输入回显、`cat` 出来的密钥：默认关、逐次允许、遮盖三者都要有
- 全屏程序（vim、htop、tmux）读到的是当前屏幕而不是滚动历史，要在结果里说明
- 手机端没有命令行 / MCP，不涉及

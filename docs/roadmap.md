# 计划清单

想做但还没做的功能。每项写清楚现状、打算怎么做、要注意什么；开始做时从这里挪到 CHANGELOG 的 `[Unreleased]`，做完删掉。

## 外部 AI 读取已打开标签的终端内容

> 状态：待定（2026-10-21 记下）

**现状**

- **终端里的 AI 助手**（网页版 Agent，Worker 里跑）已经能看到这个会话的终端输出：Worker 为每个会话留着最近约 5 万字符的原始输出，每一步自动带上最后 200 行（最多 4000 字），模型还能用 `read_terminal_context` 工具多读一些（最多 1.6 万字）。只限这条连接；带颜色控制码；完整重连后清空。
- **通过命令行 / MCP 接入的外部 AI**（Claude Code、Codex、Cursor、远程 MCP……）看不到你开着的标签：它们的工具（`exec`、`read_file`、`start_job` 等）都在单独的通道上执行，只能自己再跑一遍命令了解状态，不知道你刚才在终端里输入了什么、看到了什么。

**打算**

- 命令行与 MCP 增加两个只读工具：列出桌面客户端里开着的会话（标签名、主机 ID、连接状态），以及读取某个会话终端最近若干行（去掉颜色控制码，按 xterm 屏幕与回滚内容取，不是原始字节流）
- 经桌面客户端读取（客户端开着才有，与 AI 跨服务器操作同一条本机通道），不经 Worker
- **默认关**；打开后每次读取在客户端弹出允许（可选“这个会话本次都允许”），设置里能看到最近被读过的记录
- 结果有界（行数与字数上限），并照命令行现有规则对疑似密钥、令牌做遮盖；终端内容在给模型时标成不可信数据，不构成操作授权
- 远程 MCP 不提供（读的是本机客户端，云端碰不到）

**要注意**

- 终端里可能有密码提示后的输入回显、`cat` 出来的密钥：默认关、逐次允许、遮盖三者都要有
- 全屏程序（vim、htop、tmux）读到的是当前屏幕而不是滚动历史，要在结果里说明
- 手机端没有命令行 / MCP，不涉及

## 终端连接中继：断线时由我们的 Worker 继续连着官方 Worker

> 状态：待定（2026-10-21 记下；先做了客户端侧的恢复与诊断改进，看日志再决定）

**现状**

- 恢复会话只在官方 Worker 已经察觉旧连接断开、把会话放进 60 秒保持期之后才认。经过系统代理 / TUN 时，客户端这头断了，Worker 那头往往要过一会儿才察觉（代理没把断开传过去），这段时间里恢复以 404 拒绝。客户端现在会接着试 20 秒；察觉得更晚、或者旧连接一直半死不活，就只能开新 Shell。
- 网页版心跳超时后以 1000 关闭，关闭帧若还送得到 Worker，会被当成正常结束、直接销毁会话。客户端已改为最近 20 秒内收到过消息就不判定卡死，减少误判，但没法完全避免。
- 官方 Worker 重新部署（或 Cloudflare 重启它的 Durable Object）时，所有会话都会丢，任何方案都救不了，只能避开工作时间部署。

**打算**

- 在我们自己的 Worker（AI 增强代理或伴侣 Worker）里加一个 Durable Object 做终端 WebSocket 中继：客户端连中继，中继连官方 `/api/ssh`（服务端 fetch 可以带上同源 Origin）。客户端这头断了，中继那条到官方 Worker 的连接照常连着，官方 Worker 完全感觉不到断线；客户端重连到同一个中继对象，补发断线期间缓存的输出后接着用
- 中继要原样转发协议，并处理：`session_created` 里的恢复凭据换成中继自己的；断线期间替客户端回输出确认（有上限，超了就停止确认、让上游背压）；中继自己到官方的连接断了，再用真实凭据向官方恢复；凭据存进 DO 存储，中继自己重新部署后也能接回
- 客户端按实例开关（实例管理里填中继地址），默认关；SFTP 仍直连
- 不改官方 Worker

**要注意**

- 额度：每个开着的会话多占一份 Durable Object 时长（出站 WebSocket 不能休眠，一条会话常驻 24 小时约 10,800 GB-s，免费额度每天 13,000 GB-s），开几个标签一整天就会超；与官方 Worker 在同一账号时额度共用。Workers Paid（$5/月）含 40 万 GB-s/月
- 部署：新增 DO 类要用 wrangler 做迁移，控制台粘贴代码的部署方式不再适用
- 多一跳延迟（同区域时几毫秒到几十毫秒）；中继对象的位置要靠近官方会话所在区域
- `REQUIRE_GITHUB_AUTH=true` 时官方 `/api/ssh` 升级还要会话 Cookie，中继需要客户端转交
